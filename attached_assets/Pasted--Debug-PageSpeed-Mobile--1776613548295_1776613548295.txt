أريد Debug دقيق لتراجع PageSpeed Mobile بعد آخر تحسينات الأداء.

المشكلة الحالية:
بعد التعديلات الأخيرة، Performance انخفض بدل أن يتحسن:
- Performance ≈ 71
- LCP ≈ 9.8s
- بينما FCP/TBT/CLS ما زالت جيدة

هذا يعني أن هناك عنصرًا رئيسيًا في أول الشاشة أصبح يتأخر جدًا في الظهور.

🔹 المطلوب:
أريدك أن تحلل سبب تراجع LCP بدقة، ثم تطبق rollback جزئي وآمن فقط على الجزء المسبب للمشكلة، بدون التراجع عن كل التحسينات.

---

### 1) تحديد عنصر LCP الحقيقي حاليًا
- حدّد ما هو عنصر LCP الحالي في الصفحة الرئيسية على الموبايل:
  - هل هو صورة Hero؟
  - نص داخل السلايدر؟
  - أول PropertyCard؟
  - Skeleton/placeholder؟
  - عنصر يتم تحميله بعد hydration؟

- أعطني اسم الملف والمكوّن المسؤول.

---

### 2) مراجعة آخر تحسينات الصفحة الأولى فقط
راجع خصوصًا:
- dynamic import
- ssr: false
- skeleton placeholders
- أي lazy loading
- أي useMemo / memo / split
- أي تأجيل لتحميل Hero أو ImageSlider أو القسم الأول في الصفحة

---

### 3) قاعدة مهمة جدًا
- أي مكوّن موجود Above the Fold أو قد يكون LCP:
  ❌ لا تجعله dynamic import مع ssr: false
  ❌ لا تؤخره إلى ما بعد hydration
  ❌ لا تضعه lazy إذا كان هو أول عنصر مهم

- بدلاً من ذلك:
  ✅ اجعله SSR أو rendered مباشرة
  ✅ اجعل صورة LCP فقط:
     priority
     fetchPriority="high"
     loading="eager"

---

### 4) المطلوب غالبًا
إذا كان Hero/ImageSlider أو أول banner هو سبب المشكلة:
- ألغِ dynamic import عنه فقط
- ألغِ ssr: false عنه فقط
- اجعل أول slide أو أول hero image render مباشرة من السيرفر
- أبقِ الصور أو الشرائح الأخرى lazy
- لا تؤخر أول عنصر مرئي مهم

---

### 5) أبقِ التحسينات المفيدة
لا تتراجع عن:
- تحسين الصور إلى WebP/AVIF
- ضبط sizes
- memo لـ PropertyCard إذا لم يكن يسبب مشكلة
- lazy للصور التي تحت fold
- أي تحسينات ليست مؤثرة على عنصر LCP

---

### 6) افحص إذا كان skeleton نفسه أصبح LCP
إذا كان placeholder أو skeleton هو الذي يظهر أولًا ثم يستبدل لاحقًا بمحتوى أكبر:
- قلل حجمه
- أو اجعل المحتوى الحقيقي يظهر مباشرة
- أو امنع أن يكون skeleton هو العنصر الأكبر

---

### 7) افحص الـ API dependency
إذا أول شاشة تنتظر API قبل ظهور العنصر الأكبر:
- حاول render مبدئي ثابت أو SSR لأول section
- لا تجعل أول عنصر بصري أساسي يعتمد على client-side fetch فقط

---

### 8) المطلوب في النهاية
أعطني:
- السبب الحقيقي لتراجع LCP
- ما الذي قمت بإلغائه أو تعديله
- الملفات التي عدلتها
- هل كان السبب:
  dynamic import / ssr false / lazy / skeleton / API delay / hero slider

مهم جدًا:
لا أريد refactor كبير.
أريد إصلاحًا جراحيًا فقط لتراجع LCP.
