أريد بناء نظام باقات احترافي يدعم أكثر من منتج داخل المنصة، لكن بشروط صارمة جدًا.

🚨 لا تبدأ في تنفيذ أي كود الآن.

أولًا:
حلل نظام الباقات الحالي بالكامل:
- Plan
- PlanFeature
- FeatureDefinition
- Subscription
- أي علاقة حالية بين المستخدم والباقات
- صفحة إدارة الخطط
- منطق limits/features الحالي

ثم قدم خطة فقط بدون كود.

----------------------------------

الهدف:

لدينا أكثر من خط ربح في المنصة:

1) listings
- باقات الإعلانات والعقارات الحالية

2) matching
- باقات الوصول للطلبات / العملاء المحتملين / Lead Matching

مطلوب دعم الاثنين بشكل احترافي بدون كسر النظام الحالي.

----------------------------------

المطلوب في التصميم:

1) إضافة مفهوم PlanCategory أو ProductArea:
- listings
- matching
- لاحقًا يمكن إضافة verification أو daily_rentals

2) لا تحذف أي باقة موجودة.
3) لا تغيّر behavior الباقات الحالية.
4) اجعل الباقات الحالية افتراضيًا category = listings إذا لم يكن لها category.
5) أضف إمكانية إنشاء باقات matching مستقلة لاحقًا.

----------------------------------

المطلوب تحليله في الخطة:

1) ما هي أقل تعديلات DB المطلوبة؟
مثلاً:
- Plan.Category أو Plan.ProductArea
أم جدول منفصل؟
اختر الأقل خطرًا.

2) كيف سيتم فصل Features؟
مثال:
- listing features:
  max_ads, featured_ads, direct_whatsapp...
- matching features:
  lead_notifications, monthly_lead_unlocks, instant_notifications, full_match_access, search_priority

3) كيف يتم تحديد اشتراك المستخدم؟
هل المستخدم يمكن أن يملك:
- اشتراك listings
- اشتراك matching
- أو الاثنين معًا

4) كيف تتعامل مع المستخدمين الحاليين؟
- لا تكسر اشتراكات حالية
- لا تغيّر صلاحياتهم الحالية

5) كيف ستتغير لوحة إدارة الخطط؟
- إضافة فلتر/تبويب حسب category فقط
- بدون إعادة تصميم كامل

6) كيف ستقرأ الأنظمة المختلفة الباقات:
- نظام الإعلانات يقرأ listings فقط
- نظام matching يقرأ matching فقط

----------------------------------

قواعد إلزامية:

1) Additive only
2) ممنوع refactor عام
3) ممنوع حذف أو إعادة تسمية أي feature موجود
4) ممنوع كسر صفحة إدارة الخطط الحالية
5) ممنوع تعديل pricing logic الحالي بشكل جذري
6) ممنوع لمس نظام الدفع الحقيقي إن وجد
7) لا تبدأ التنفيذ قبل موافقتي

----------------------------------

بعد التحليل:
اعطني:
- الملفات المتوقع تعديلها
- الجداول/الحقول المقترحة
- migration strategy آمنة
- plan للتنفيذ على مراحل
- المخاطر المحتملة وكيف تمنعها

ثم توقف وانتظر موافقتي.
