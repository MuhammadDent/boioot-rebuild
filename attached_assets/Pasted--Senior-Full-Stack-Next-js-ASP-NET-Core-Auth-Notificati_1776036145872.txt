أريدك أن تعمل كخبير **Senior Full Stack (Next.js + ASP.NET Core + Auth + Notifications + Messaging UX)** وتقوم **بتشخيص وتنفيذ تعديل فعلي** في مشروع **Boioot** بدون تخمين.

## السلوك الحالي غير المطلوب

عندما تصل رسالة جديدة إلى مستخدم من عضو آخر، ثم يقوم هذا المستخدم بتسجيل الدخول، يفتح النظام حسابه مباشرة على **صفحة الرسائل / المحادثات**.

هذا السلوك غير مناسب.

## السلوك المطلوب

أريد بعد تسجيل الدخول أن يتم توجيه المستخدم إلى:

* **الصفحة الرئيسية للموقع** وليس صفحة الرسائل

لكن في نفس الوقت، إذا كان لديه **رسالة جديدة / محادثة غير مقروءة**، يجب أن يشعر بذلك بوضوح من خلال:

* Badge / indicator / counter على أيقونة الرسائل
* أو أي تنبيه بصري واضح ومهني
* بدون إجباره على فتح صفحة الرسائل مباشرة

## المطلوب منك

أريد منك فحص **منطق تسجيل الدخول + redirect + الإشعارات/الرسائل غير المقروءة** بالكامل، ثم تنفيذ التعديل فعليًا.

### 1) شخّص السبب الحقيقي

افحص لماذا بعد تسجيل الدخول يتم فتح صفحة الرسائل:

* هل يوجد redirect ثابت إلى `/messages` أو `/dashboard/messages`؟
* هل يوجد logic يعتمد على وجود محادثات؟
* هل هناك `router.push` أو `redirect()` بعد login موجه إلى الرسائل؟
* هل هناك `next` parameter أو returnUrl يتم ضبطه خطأ؟
* هل middleware أو auth callback أو session handler يفرض هذا التوجيه؟
* هل السبب من frontend أم backend أم كليهما؟

### 2) افحص الملفات الفعلية المتعلقة بهذه الجزئية

راجع الكود الحقيقي في:

* صفحة تسجيل الدخول
* submit handler الخاص بالـ login
* auth context / auth store / session handling
* middleware إن وجد
* route guards
* header / top navigation
* messages icon / notification badge
* API الخاصة بعدد الرسائل غير المقروءة
* أي polling / fetch / unread count logic
* أي redirect logic بعد تسجيل الدخول

### 3) نفّذ السلوك الجديد المطلوب

بعد تسجيل الدخول الناجح:

* يتم توجيه المستخدم إلى **الصفحة الرئيسية** `/`
* وليس إلى صفحة الرسائل

إلا إذا كان هناك حالة خاصة صريحة جدًا مثل:

* كان يحاول فتح صفحة محمية معينة قبل تسجيل الدخول
* وعندها فقط يعود لتلك الصفحة المطلوبة

أما الدخول العادي من صفحة login:

* يجب أن يذهب إلى الرئيسية

### 4) أضف تنبيه واضح لوجود رسالة جديدة

بدل فتح صفحة الرسائل مباشرة، أريدك أن تجعل المستخدم يعرف أن لديه رسالة من خلال:

* Badge واضح على أيقونة الرسائل
* عدد الرسائل غير المقروءة إن وجد
* أو dot indicator إذا كان هذا أنسب
* ويعمل على:

  * الجوال
  * الديسكتوب

### 5) متطلبات UX

أريد سلوكًا احترافيًا:

* لا يتم فرض صفحة الرسائل على المستخدم بعد login
* يبقى الدخول طبيعيًا إلى الصفحة الرئيسية
* تظهر أيقونة الرسائل بحالة واضحة إذا توجد رسائل غير مقروءة
* عند فتح صفحة الرسائل يتم تحديث حالة unread بشكل صحيح
* لا يوجد lag أو سلوك مربك
* لا يتم كسر أي redirect مشروع آخر في النظام

### 6) راجع منطق الـ redirect كامل

أريدك أن تراجع:

* login redirect
* logout redirect
* protected routes redirect
* next/returnUrl logic
* deep linking logic

وتتأكد أن:

* الصفحة الرئيسية هي الوجهة الافتراضية بعد تسجيل الدخول
* الرسائل لا تُفرض كوجهة افتراضية
* إذا جاء المستخدم من رابط محدد قبل login يعود له فقط، وليس للرسائل عشوائيًا

### 7) المطلوب في النهاية

بعد الفحص والتنفيذ أعطني تقريرًا واضحًا:

* ما السبب الحقيقي الذي كان يفتح صفحة الرسائل بعد login؟
* ما الملفات التي عدلتها؟
* ما الذي أصلحته بالضبط؟
* هل أصبحت الصفحة الرئيسية هي الصفحة الافتراضية بعد تسجيل الدخول؟
* هل يظهر تنبيه واضح لوجود رسائل غير مقروءة؟
* وهل يعمل ذلك على الجوال والديسكتوب؟

## مهم جدًا

* لا تعطيني احتمالات عامة
* لا تكتفِ بالشرح
* افحص الكود الفعلي
* نفّذ التعديل بنفسك
* أصلح redirect + unread indicator معًا

ابدأ الآن من صفحة تسجيل الدخول ومنطق redirect بعدها، ثم تتبع نظام الرسائل غير المقروءة، ونفّذ السلوك المطلوب بالكامل.
