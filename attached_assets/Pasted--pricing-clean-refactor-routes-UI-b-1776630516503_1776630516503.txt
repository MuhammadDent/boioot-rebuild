أريد إصلاح صفحة `/pricing` بشكل clean وآمن جدًا، بدون أي refactor كبير وبدون تغيير routes أو UI أو backend أو API contract.

🔹 المشكلة الحالية:
في صفحة `/pricing` يوجد spinner لا ينتهي للمستخدم غير المسجل دخولًا.
السبب أن الصفحة تطلب:
`GET /api/dashboard/subscription/current`
ثم يرجع `401 Unauthorized`
لكن الـ UI لا يتعامل مع هذه الحالة بشكل صحيح، فيبقى loading spinner ظاهرًا.

---

## الهدف

أريد أن تعمل صفحة `/pricing` بشكل صحيح في حالتين:

### 1) المستخدم غير مسجل دخولًا
- لا يظهر spinner للأبد
- تظهر صفحة الباقات بشكل طبيعي
- إذا كان هناك جزء خاص بالاشتراك الحالي، يظهر له state مناسبة مثل:
  - "سجل دخول لعرض اشتراكك الحالي"
  أو
  - تجاهل جزء الاشتراك الحالي نهائيًا للمستخدم غير المسجل

### 2) المستخدم مسجل دخولًا
- تبقى الصفحة تعمل كالمعتاد
- يتم جلب الاشتراك الحالي وعرضه إن وجد

---

## قواعد صارمة جدًا

1) لا تغيّر route
- يجب أن تبقى الصفحة:
  `/pricing`

2) لا تغيّر التصميم العام
- نفس layout
- نفس البطاقات
- نفس ترتيب العناصر
- نفس النصوص الأساسية ما أمكن
- لا تغيّر CSS إلا إذا كان ضروريًا جدًا

3) لا تغيّر backend أو API
- لا تغيّر endpoint
- لا تغيّر response shape
- لا تغيّر auth logic في السيرفر

4) لا تعمل refactor كبير
- أريد أقل تعديل ممكن
- وأقل عدد ملفات ممكن
- وتعديل قابل للتراجع بسهولة

---

## المطلوب تقنيًا

### أ) التعامل الصحيح مع 401
إذا طلب:
`/api/dashboard/subscription/current`
وأعاد `401`

فهذا ليس crash، وليس loading دائم.

أريد أن تعتبره حالة متوقعة للمستخدم غير المسجل، وليس خطأ قاتل.

---

### ب) loading state الصحيح
- spinner يجب أن يظهر فقط أثناء الطلب الحقيقي
- إذا رجع 401 أو انتهى الطلب:
  - أوقف loading
  - اعرض الصفحة بشكل طبيعي

---

### ج) unauthorized state
للمستخدم غير المسجل:

- إمّا:
  - تعرض الباقات فقط بدون current subscription block
- أو:
  - تعرض الباقات + رسالة بسيطة داخل section الاشتراك الحالي:
    "سجل دخول لعرض اشتراكك الحالي"

اختر الخيار الأنظف بأقل تغيير على الـ UI الحالي.

---

### د) authenticated state
للمستخدم المسجل:
- أبقِ السلوك الحالي كما هو
- جلب الاشتراك الحالي يجب أن يستمر بالعمل

---

## المطلوب قبل التنفيذ
اعرض لي أولًا باختصار:

1. ما الملف المسؤول عن `/pricing`
2. أين يوجد loading state الحالي
3. أين يتم استدعاء `/api/dashboard/subscription/current`
4. ما أقل تعديل ممكن لحل المشكلة

ثم بعد ذلك نفّذ.

---

## المطلوب بعد التنفيذ
أعطني تقريرًا واضحًا جدًا يشمل:

1. الملفات التي تغيرت فقط
2. ما الذي كان يسبب spinner اللانهائي
3. كيف تم التعامل مع 401
4. هل تغيّر route؟ (يجب: لا)
5. هل تغيّر UI؟ (يجب: لا أو تغيير طفيف جدًا)
6. هل الصفحة تعمل الآن لغير المسجل؟
7. هل الصفحة ما زالت تعمل للمسجل؟

---

## اختبارات إلزامية
بعد التنفيذ تحقق من:

- `/pricing` يفتح بدون spinner دائم للمستخدم غير المسجل
- لا يوجد runtime error
- لا يوجد crash
- الباقات تظهر بشكل طبيعي
- إذا كان المستخدم غير مسجل لا يبقى loading للأبد
- إذا كان المستخدم مسجل، ما زال current subscription يعمل
- لا يوجد كسر في التصميم

- توقف
- لا تنفذ refactor كبير
- واشرح لي أين المشكلة
- واقترح خيارًا أصغر وأكثر أمانًا

أريد إصلاحًا جراحيًا فقط.
