أريدك أن تعمل كخبير **Senior Full Stack (Next.js + ASP.NET Core + Admin Dashboard + PostgreSQL)** وتقوم **بتشخيص وإصلاح مشكلة فعلية** في مشروع **Boioot** بدون تخمين.

## المشكلة الحالية

أنا دخلت بحساب **Admin** إلى لوحة التحكم، ثم إلى صفحة:

`/dashboard/admin/users`

وفي قائمة المستخدمين يظهر لكل مستخدم أزرار مثل:

* **تفاصيل**
* **تعديل**
* **التوثيق**

لكن عند الضغط على:

* **تفاصيل**
* أو **تعديل**

لا يتم فتح أي شيء، أو لا تظهر الصفحة المطلوبة، أو لا يوجد انتقال فعلي، أو الزر لا ينفذ الوظيفة المطلوبة.

بمعنى آخر:
**زر التفاصيل وزر التعديل لا يعملان فعليًا من صفحة المستخدمين داخل لوحة الإدارة.**

## المطلوب منك

أريد منك أن تفحص هذه المشكلة **عمليًا** وتصلحها بالكامل.

### 1) تشخيص دقيق للمشكلة

افحص السبب الحقيقي، وحدد هل الخلل من:

* زر `Link` أو `onClick`
* `router.push`
* route غير موجود
* route موجود لكن اسم المسار خاطئ
* dynamic route غير معرف
* الصفحة موجودة لكن لا يتم تمرير `id`
* مشكلة permission / guard / redirect
* component داخل الجدول لا يستقبل البيانات الصحيحة
* خطأ JavaScript في المتصفح
* خطأ في App Router
* أو أن الصفحات الخاصة بالتفاصيل والتعديل غير موجودة أصلًا

### 2) افحص الملفات المتعلقة فعليًا

راجع الكود الحقيقي المتعلق بـ:

* صفحة `/dashboard/admin/users`
* الكومبوننت الذي يرسم كروت أو صفوف المستخدمين
* أي زر أو menu خاص بـ:

  * تفاصيل المستخدم
  * تعديل المستخدم
* ملفات routes الخاصة بالإدارة
* صفحات:

  * user details
  * user edit
* أي dynamic route مثل:

  * `app/dashboard/admin/users/[id]/page.tsx`
  * `app/dashboard/admin/users/[id]/edit/page.tsx`
  * أو أي بنية مشابهة موجودة فعلًا في المشروع
* أي guard / middleware / permission logic
* أي API call يتم تنفيذها عند فتح التفاصيل أو التعديل

### 3) أريد تقريرًا واضحًا عن السبب الحقيقي

حدد بدقة:

* ما هو الزر الذي لا يعمل؟
* هل الضغط لا ينفذ أي حدث أصلًا؟
* أم يتم الانتقال إلى route خاطئ؟
* أم أن route غير موجود؟
* أم أن الصفحة تفتح لكن تفشل في تحميل بيانات المستخدم؟
* أم أن هناك silent error في console؟

### 4) أصلح المشكلة فعليًا

أريدك أن تقوم بالتعديل في الملفات اللازمة حتى يصبح التالي يعمل 100%:

#### عند الضغط على "تفاصيل"

* يتم الانتقال إلى صفحة تفاصيل المستخدم الصحيحة
* يتم تمرير `userId` الصحيح
* يتم تحميل بيانات المستخدم بنجاح
* تظهر رسالة خطأ واضحة إذا كان المستخدم غير موجود

#### عند الضغط على "تعديل"

* يتم الانتقال إلى صفحة تعديل المستخدم الصحيحة
* يتم تمرير `userId` الصحيح
* يتم تحميل البيانات داخل النموذج
* يمكن تعديل المستخدم وحفظ التعديلات

### 5) راجع الـ routing كامل لهذه الجزئية

تأكد من أن كل المسارات الخاصة بالمستخدمين في لوحة الإدارة صحيحة، مثل:

* صفحة قائمة المستخدمين
* صفحة تفاصيل المستخدم
* صفحة تعديل المستخدم

وتأكد أن:

* كل `Link`
* وكل `router.push`
* وكل dynamic segment
* وكل اسم مجلد في `app/`

متطابق فعليًا مع المسار المستخدم في الكود.

### 6) راجع الصلاحيات والحماية

بما أن هذه صفحة Admin:

* تأكد أن المستخدم الإداري فقط هو من يستطيع الوصول
* وتأكد أن الحماية لا تمنع التفاصيل أو التعديل بالخطأ
* وإذا كانت هناك guard أو redirect logic خاطئة، أصلحها

### 7) نفّذ التعديل ولا تكتفِ بالشرح

بعد اكتشاف السبب:

* عدّل الملفات فعليًا
* أصلح الأزرار والمسارات
* ثم أعطني في النهاية:

  * السبب الحقيقي
  * الملفات التي عدلتها
  * ما الذي أصلحته بالضبط
  * هل تفاصيل المستخدم تعمل الآن؟
  * هل التعديل يعمل الآن؟

## مهم جدًا

* لا تعطيني احتمالات عامة
* لا تعطيني تفسيرًا نظريًا فقط
* افحص الكود الفعلي
* نفّذ الإصلاح بنفسك
* ثم أعطني نتيجة نهائية واضحة

ابدأ الآن من صفحة:
`/dashboard/admin/users`
ثم تتبع زر **تفاصيل** وزر **تعديل** حتى أصل السبب الحقيقي وتصلحه بالكامل.
