أريدك الآن أن تبدأ **مرحلة Frontend Integration لنظام الصور** في مشروع **Boioot** بشكل احترافي، مع الحفاظ على التوافق مع الـ API الحالية التي أصبحت جاهزة.

## الهدف

بناء تجربة رفع صور احترافية في الواجهة الأمامية، تدعم:

1. **Image Preview محلي**
2. **رفع الصور فعليًا إلى backend**
3. **الاحتفاظ بـ imageId و url**
4. **اختيار Cover Image**
5. **إعادة ترتيب الصور**
6. **ربط الصور بالعقار أو المشروع عند الحفظ**
7. **حذف الصورة من الواجهة ومن النظام بشكل صحيح**

---

# السياق الحالي للـ API

الـ backend الآن يدعم:

* `POST /api/upload/image`
* `POST /api/images/attach`
* `POST /api/images/{id}/set-cover`
* `POST /api/images/reorder`
* `DELETE /api/images/{id}/detach`
* `DELETE /api/images/{id}`
* `GET /api/images/{entityType}/{entityId}`

والنظام deployed ويعمل.

---

# المطلوب منك الآن

## 1) افحص مكان نموذج إضافة/تعديل العقار في الـ frontend

ابدأ بتحديد:

* أين توجد صفحة إنشاء العقار
* أين توجد صفحة تعديل العقار
* أين أفضل مكان لإضافة image uploader component
* كيف تُدار state الحالية للنموذج

أريد أولًا تقريرًا مختصرًا جدًا:

* الملفات المسؤولة عن create/edit property
* أفضل مكان لدمج component الصور
* هل يوجد component جاهز قريب يمكن البناء عليه

---

## 2) أنشئ ImageUploader Component احترافي

أريد component مستقل قابل لإعادة الاستخدام، مثل:

* `PropertyImageUploader`
* أو `ImageUploader`

يدعم على الأقل:

### اختيار صور متعددة

* من input file
* ويفضل drag & drop إذا كان سهلًا دون تعقيد كبير

### Preview محلي

قبل الرفع باستخدام:

* `URL.createObjectURL(file)`

### حالات واضحة لكل صورة

مثل:

* `pending`
* `uploading`
* `uploaded`
* `failed`

### تخزين بيانات كل صورة في state

مثل:

* `localId`
* `file`
* `previewUrl`
* `uploadedImageId`
* `uploadedUrl`
* `status`
* `isCover`
* `sortOrder`

---

## 3) تنفيذ الرفع الفعلي

أريد عند اختيار الصور:

* يبدأ الرفع إلى:

  * `POST /api/upload/image`
* باستخدام `multipart/form-data`
* ثم يتم حفظ:

  * `imageId`
  * `url`
  * metadata اللازمة

إذا فشل رفع صورة:

* لا تكسر بقية الصور
* أظهر حالة failed
* واجعل هناك طريقة لإعادة المحاولة أو حذفها من القائمة

---

## 4) Cover selection

أريد في الواجهة إمكانية اختيار صورة واحدة كـ Cover:

* إذا اختار المستخدم صورة كـ cover:

  * يتم تحديث الـ state محليًا
  * تبقى صورة واحدة فقط `isCover = true`

ولا نرسل `set-cover` فورًا إذا كان العقار لم يُحفظ بعد
بل نؤجله إلى ما بعد إنشاء العقار وربط الصور.

أما إذا كانت صفحة **Edit Property** لعقار موجود:

* يمكن تنفيذ `set-cover` مباشرة أو عند الحفظ النهائي
* اختر الأسلوب الأنظف ووضح السبب

---

## 5) Reorder UI

أريد دعم ترتيب الصور في الواجهة.

إذا كان drag & drop سهلًا وموجودًا في المشروع، نفذه
وإذا كان سيأخذ وقتًا أو تعقيدًا كبيرًا:

* ابدأ بأزرار:

  * Move Left / Move Right
  * أو Move Up / Move Down

المهم:

* ترتيب الصور يجب أن ينعكس في `sortOrder` داخل state
* ويُرسل لاحقًا إلى:

  * `POST /api/images/reorder`

---

## 6) Create Property flow

في صفحة إنشاء عقار جديد، أريد التدفق كالتالي:

### أثناء الرفع

* الصور تُرفع أولًا إلى النظام
* نحصل على:

  * `imageId`
  * `url`

### عند حفظ العقار

بعد نجاح إنشاء العقار:

1. يتم استدعاء:

   * `POST /api/images/attach` لكل صورة
2. ثم:

   * `POST /api/images/reorder`
3. ثم:

   * `POST /api/images/{id}/set-cover` للصورة المختارة كغلاف

رتب التنفيذ بحيث يكون robust:

* إذا فشل attach لبعض الصور، أظهر خطأ واضح
* لا تجعل التجربة غامضة

---

## 7) Edit Property flow

في صفحة تعديل عقار موجود:

* اجلب الصور الحالية من API
* اعرضها داخل نفس component
* اسمح بالإضافة
* اسمح بالحذف
* اسمح بتغيير cover
* اسمح بإعادة الترتيب

واحرص أن الواجهة تدعم:

* الصور القديمة legacy
* الصور الجديدة user_upload

بما أن الـ backend الآن يدعم النظامين

---

## 8) Delete behavior

أريد سلوكًا واضحًا:

### إذا كانت الصورة لم تُرفع بعد

* احذفها من state فقط

### إذا كانت رُفعت لكن لم تُربط بعد

* احذفها من النظام عبر:

  * `DELETE /api/upload/{id}` أو endpoint الأنسب الموجود عندكم

### إذا كانت مرتبطة بعقار موجود

* اختر السلوك الأنظف:

  * إما delete كامل
  * أو detach أولًا حسب الحالة
* ووضح القرار

---

## 9) UX مهم جدًا

أريد واجهة مرتبة وواضحة:

* صورة cover عليها badge واضحة
* حالة uploading واضحة
* حالة failed واضحة
* أزرار حذف واضحة
* ترتيب الصور مفهوم
* لا أريد تجربة مربكة
