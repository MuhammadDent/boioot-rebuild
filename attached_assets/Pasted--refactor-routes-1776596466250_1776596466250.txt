أريد إظهار حالة التوثيق بصريًا في واجهات الإعلانات والمعلنين، بدون refactor كبير وبدون كسر أي routes أو backend contracts.

المشكلة الحالية:

* نظام التوثيق موجود ويعمل
* تمت مراجعة المستويات وأسماؤها في الـ admin
* لكن في صفحات عرض الإعلانات وصفحة تفاصيل العقار لا تظهر أي علامة توضح هل المعلن موثق أم لا، وهل هناك حالة توثيق مرتبطة بالإعلان أم لا

المطلوب:
تنفيذ minimal safe UI integration فقط لإظهار badges التوثيق في الواجهات العامة، مع إعادة استخدام المنطق الحالي قدر الإمكان.

نفّذ بالترتيب:

1. افحص ما إذا كانت بيانات المستخدم أو الإعلان القادمة للـ frontend تحتوي أحد الحقول التالية أو ما يعادلها:

* verificationLevel
* isVerified
* verificationStatus
* verifiedAt
* user.verificationLevel
* owner.verificationLevel
* advertiser.verificationLevel

2. حدّد المصدر الحقيقي لحالة التوثيق:

* هل هو توثيق المستخدم؟
* أم توثيق الإعلان؟
* أم كلاهما؟
  ثم استخدم الموجود فعليًا فقط، بدون اختراع logic جديد

3. في صفحة تفاصيل العقار/property details:

* أضف badge واضحة بجانب اسم المعلن أو صورته لعرض حالة توثيق المعلن
* إذا كانت البيانات المتاحة تسمح، أضف badge ثانية قرب عنوان الإعلان أو رقم الإعلان لعرض حالة توثيق الإعلان
* إذا لم يكن توثيق الإعلان متاحًا فعليًا من البيانات، اعرض فقط توثيق المعلن

4. في بطاقات الإعلانات listings/cards:

* أضف indicator صغير وواضح لحالة توثيق المعلن أو الإعلان حسب البيانات المتاحة
* لا تغيّر layout بشكل كبير
* لا تكسر التصميم الحالي
* اجعل التغيير minimal وهادئ بصريًا

5. استخدم التسميات الحالية المعتمدة لمستوى التوثيق إذا كان verificationLevel موجودًا:

* 0 => غير موثق
* 1 => موثق هوية
* 2 => موثق ملكية
* 3 => موثق نشاط تجاري

6. إذا كان المتاح فقط boolean مثل isVerified:

* true => موثق
* false => غير موثق

7. إذا لم تكن بيانات التوثيق تصل إلى بعض الصفحات:

* أضف أقل تعديل ممكن في frontend fetching أو mapping لتمرير هذه الحقول فقط
* لا تغيّر backend contracts إلا إذا كان الحقل موجودًا أصلًا ولا يتم استهلاكه
* لا تعمل refactor كبير

8. أنشئ helper/component صغير قابل لإعادة الاستخدام إذا لزم، مثل:

* VerificationBadge
  لكن بدون overengineering

9. مهم جدًا:

* لا تعرض badge غير حقيقية
* لا تفترض وجود توثيق إعلان إذا النظام لا يوفّره
* استخدم فقط البيانات الفعلية القادمة من النظام

10. في النهاية أعطني:

* هل التوثيق المتاح حاليًا هو للمستخدم أم للإعلان أم لكليهما
* الملفات التي عدّلتها
* أين أضفت badges بالضبط
* هل احتجت فقط display changes أم أيضًا mapping/fetching صغير في frontend
