أريدك أن تعمل كخبير **Senior Full Stack (Next.js + ASP.NET Core + File Upload + PostgreSQL/Object Storage)** وتقوم **بتشخيص وإصلاح مشكلة فعلية** في مشروع **Boioot** بدون تخمين.

## المشكلة الحالية

أنا داخل **الملف الشخصي** لحساب مستخدم على **الجوال**، وفي تبويب **الصورة الشخصية** قمت برفع صورة، لكن ظهرت رسالة خطأ تقول:

**"حجم الصورة يجب أن لا يتجاوز 2MB."**

أريد التأكد هل المشكلة فعلًا بسبب:

* أن حجم الصورة أكبر من 2MB
* أو أن هناك bug في التحقق من الحجم
* أو أن الحساب بالبايت/الميغابايت خاطئ
* أو أن الواجهة ترفض الصورة خطأً حتى لو كانت ضمن الحد
* أو أن الضغط / التحويل / المعالجة في frontend أو backend فيها خلل
* أو أن الرسالة المعروضة عامة وغير دقيقة

## المطلوب منك

أريد منك فحص **نظام رفع الصورة الشخصية بالكامل** ثم إصلاح المشكلة فعليًا.

### 1) افحص الكود الحقيقي المتعلق برفع الصورة الشخصية

راجع الملفات المتعلقة بـ:

* صفحة الملف الشخصي
* تبويب الصورة الشخصية
* مكوّن رفع الصورة
* input type="file"
* أي validation في frontend
* أي دالة:

  * `handleImageUpload`
  * `onFileChange`
  * `uploadAvatar`
  * أو ما يشابهها
* أي service / api client / fetch / axios خاص برفع الصور
* أي endpoint في ASP.NET Core خاص بـ:

  * رفع الصورة الشخصية
  * تحديث بيانات المستخدم
* أي validation في backend لحجم الملف أو نوعه
* أي storage logic:

  * local storage
  * uploads folder
  * cloud/object storage
* أي middleware أو form-data parsing logic

### 2) شخّص السبب الحقيقي

أريد تقريرًا واضحًا ودقيقًا:

* ما الحجم الحقيقي للصورة التي يرفعها المستخدم؟
* هل frontend يرفضها قبل الإرسال؟
* أم backend يرفضها بعد الإرسال؟
* هل حد 2MB مطبق فعليًا بشكل صحيح؟
* هل هناك تحويل units خاطئ؟
* هل الرسالة تظهر لكل الملفات حتى لو كانت صغيرة؟
* هل المشكلة في MIME type أو extension لكن الرسالة تعرض سببًا خاطئًا؟
* هل الجوال يرسل نسخة أكبر من المتوقع؟
* هل هناك مشكلة مع HEIC / JPG / PNG / WebP؟

### 3) أصلح المشكلة فعليًا

أريدك أن تجعل رفع الصورة الشخصية يعمل بشكل احترافي كالتالي:

#### إذا كانت الصورة صالحة

* يتم قبولها
* يتم رفعها بنجاح
* يتم تحديث الصورة في الحساب
* تظهر المعاينة/الصورة الجديدة مباشرة
* تظهر رسالة نجاح واضحة

#### إذا كانت الصورة غير صالحة

* تظهر رسالة دقيقة وصحيحة فعلًا
* مثال:

  * الحجم أكبر من 2MB
  * نوع الملف غير مدعوم
  * فشل الرفع من الخادم
* لا تُعرض رسالة عامة مضللة

### 4) تحسينات مطلوبة

أريد تحسين UX أيضًا:

* عرض الحجم الفعلي للصورة عند الفشل إن لزم
* دعم الأنواع الشائعة فقط بوضوح
* تعطيل زر الحفظ أثناء الرفع
* loading state أثناء الرفع
* منع الفشل الصامت
* إذا أمكن، نفّذ ضغط/تصغير تلقائي للصورة في frontend قبل الرفع إن كانت أكبر قليلًا من الحد
* أو على الأقل اشرح للمستخدم بوضوح المطلوب

### 5) راجع frontend + backend معًا

لا أريد إصلاحًا سطحيًا.
تأكد من:

* validation في frontend
* validation في backend
* endpoint
* form-data handling
* storage
* update user profile flow
* تحديث الواجهة بعد النجاح

### 6) المطلوب في النهاية

بعد الفحص والإصلاح أعطني:

* السبب الحقيقي للمشكلة
* هل كانت الصورة فعلًا أكبر من 2MB أم لا
* الملفات التي عدلتها
* ما الذي أصلحته بالضبط
* وهل رفع الصورة الشخصية يعمل الآن بالكامل

## مهم جدًا

* لا تعطيني احتمالات عامة
* لا تكتفِ بالشرح
* افحص الكود الفعلي
* نفّذ التعديل بنفسك
* أصلح الرسالة والرفع معًا

ابدأ الآن من تبويب **الصورة الشخصية** وتتبع العملية من اختيار الملف حتى وصوله إلى backend وتخزينه، ثم أصلح السبب الحقيقي بالكامل.
