## 2) Backend business rules

Implement these rules carefully:

* Booking request is allowed only for listings where `listingType === DailyRent`
* User must be authenticated
* User cannot book their own listing
* Check-in must be before check-out
* Guest count must be >= 1
* Total nights must be calculated in backend
* Price snapshot must be calculated and stored at request time
* Prevent invalid or empty date ranges
* Prevent overlapping approved bookings for the same listing
* For now:

  * allow multiple pending requests if needed
  * but approved bookings must not overlap

---

## 3) Backend API endpoints

Create or extend API endpoints for booking requests.

Required endpoints:

### Create booking request

POST /api/bookings

Payload example:
{
"listingId": "...",
"checkInDate": "2026-04-25",
"checkOutDate": "2026-04-28",
"guestCount": 2,
"notes": "Optional note"
}

### Get current user booking requests

GET /api/bookings/my

### Get booking request details

GET /api/bookings/{id}

### Get owner booking requests for their listings

GET /api/bookings/owner

### Owner approves booking

POST /api/bookings/{id}/approve

### Owner rejects booking

POST /api/bookings/{id}/reject

### Tenant cancels booking request

POST /api/bookings/{id}/cancel

## 4) Backend validations and permissions
