أريد إغلاق صفحة `/blog` بشكل clean وآمن جدًا، بدون أي refactor كبير وبدون تغيير routes أو UI العام للموقع.

🔹 المشكلة الحالية:
صفحة `/blog` تعرض skeleton أو تبدو غير مكتملة عندما لا توجد مقالات فعلية.
هذا يعطي انطباعًا أن الصفحة broken أو ناقصة، حتى لو لم يوجد runtime error.

---

## الهدف

أريد أن تعمل صفحة `/blog` بشكل احترافي في حالتين:

### 1) إذا توجد مقالات
- اعرضها بشكل طبيعي كما هو متوقع

### 2) إذا لا توجد مقالات
- لا تعرض skeleton دائم
- لا تبدو الصفحة broken
- اعرض empty state احترافي وواضح، مثل:
  - "لا توجد مقالات متاحة حاليًا"
  - نص بسيط يوضح أن المحتوى سيُضاف لاحقًا
  - زر اختياري للرجوع للرئيسية أو صفحة العقارات

---

## قواعد صارمة جدًا

1) لا تغيّر route
- يجب أن تبقى الصفحة:
  `/blog`

2) لا تغيّر التصميم العام للموقع
- نفس layout العام
- نفس header/footer
- لا تغيّر CSS إلا إذا كان ضروريًا جدًا
- empty state يجب أن يكون متناسقًا مع تصميم الموقع

3) لا تغيّر backend أو API
- لا تغيّر endpoint
- لا تغيّر response shape
- لا تضف refactor واسع

4) لا تعمل refactor كبير
- أريد أقل تعديل ممكن
- وأقل عدد ملفات ممكن

---

## المطلوب تقنيًا

### أ) إذا كانت قائمة المقالات فارغة
أريد render واضح واحترافي بدل skeleton أو صفحة تبدو معلقة.

### ب) إذا كانت هناك مشكلة dev/local بسبب عدم وجود بيانات
اعتبرها حالة empty state وليس crash.

### ج) إذا كانت هناك مقالات
أبقِ السلوك الحالي كما هو.

---

## المطلوب قبل التنفيذ
اعرض لي أولًا باختصار:

1. ما الملف المسؤول عن `/blog`
2. كيف يتم جلب المقالات الآن
3. لماذا يظهر skeleton أو الصفحة الفارغة
4. ما أقل تعديل ممكن لإغلاق الصفحة بشكل clean

ثم بعد ذلك نفّذ.

---

## المطلوب بعد التنفيذ
أعطني تقريرًا واضحًا جدًا يشمل:

1. الملفات التي تغيرت فقط
2. ما الذي كان يسبب الشكل غير المكتمل
3. كيف أصبحت الصفحة تتصرف عند عدم وجود مقالات
4. هل تغيّر route؟ (يجب: لا)
5. هل تغيّر UI العام؟ (يجب: لا)
6. هل إذا وُجدت مقالات ما زالت تظهر طبيعيًا؟

---

## اختبارات إلزامية
بعد التنفيذ تحقق من:

- `/blog` تفتح بدون runtime error
- إذا لا توجد مقالات: تظهر empty state واضحة
- إذا توجد مقالات: تظهر القائمة طبيعيًا
- لا يوجد skeleton دائم
- لا يوجد crash
- لا يوجد كسر في التصميم

---

## مهم جدًا
إذا وجدت أن التنفيذ الآمن يحتاج refactor كبير:
- توقف
- لا تنفذ
- واشرح لي أين الخطر
- واقترح خيارًا أصغر وأكثر أمانًا

أريد إصلاحًا جراحيًا فقط.
