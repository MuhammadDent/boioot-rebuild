أريد تنفيذ تحسين احترافي وآمن على لوحة تحكم الأدمن في مشروع Boioot بدون كسر أي وظائف حالية أو التأثير على الإنتاج.

المشكلة الحالية:
- في صفحة إدارة العقارات داخل لوحة الأدمن لا يوجد زر واضح لتعديل الإعلان.
- في صفحة طلبات السوق / الطلبات الخاصة لا يوجد زر لتعديل الطلب.
- في صفحة المكاتب والوسطاء يوجد زر "تعديل الملف" لكنه لا يعمل عند الضغط عليه.
- لا يوجد خيار لتعطيل / إخفاء / تفعيل الإعلانات أو الطلبات أو حسابات المكاتب والوسطاء.
- المطلوب أن تكون الإدارة كاملة من لوحة الأدمن بشكل احترافي.

المطلوب تنفيذه:

1) إدارة العقارات (Admin Properties)
داخل:
dashboard/admin/properties

إضافة الأزرار التالية لكل كرت أو صف:
- تعديل الإعلان
- تعطيل / تفعيل الإعلان
- حذف الإعلان (مع confirmation dialog آمن)
- عرض الإعلان

الشروط:
- التعطيل لا يحذف البيانات من قاعدة البيانات.
- عند تعطيل الإعلان:
  - لا يظهر للمستخدمين في الموقع.
  - يبقى ظاهرًا في لوحة الأدمن.
- استخدام soft toggle مثل:
  isActive
  status
- الحفاظ على جميع الصلاحيات الحالية RBAC.

--------------------------------------------------

2) إدارة الطلبات الخاصة / طلبات السوق
داخل:
dashboard/admin/buyer-requests

إضافة:
- زر تعديل الطلب
- زر تعطيل / تفعيل الطلب
- زر عرض تفاصيل الطلب
- زر حذف آمن

الشروط:
- الطلب المعطل لا يظهر للمستخدمين.
- عدم كسر نظام matching أو الإشعارات.
- الحفاظ على العلاقات الحالية في قاعدة البيانات.

--------------------------------------------------

3) إصلاح زر "تعديل الملف" للمكاتب والوسطاء
داخل:
dashboard/admin/agencies

المطلوب:
- إصلاح زر "تعديل الملف" بحيث يفتح صفحة تعديل حقيقية.
- التأكد من أن الـ route صحيح.
- التأكد من عدم وجود:
  preventDefault خاطئ
  event bubbling
  disabled state
  hydration issue

النتيجة المطلوبة:
عند الضغط على:
"تعديل الملف"

يفتح:
صفحة تعديل المكتب/الوسيط مع البيانات الحالية.

--------------------------------------------------

4) إضافة نظام تعطيل / تفعيل للمكاتب والوسطاء
داخل:
dashboard/admin/agencies

إضافة زر:
- تعطيل الحساب
- إعادة التفعيل

السلوك المطلوب:
- الحساب المعطل:
  - لا يظهر للمستخدمين.
  - لا يستطيع تسجيل الدخول أو النشر.
  - تبقى بياناته محفوظة.
- عدم حذف أي بيانات أو إعلانات مرتبطة.

--------------------------------------------------

5) المتطلبات التقنية المهمة جدًا

- عدم تغيير أي API قائم إلا عند الضرورة.
- عدم تعديل بنية قاعدة البيانات بشكل خطير.
- استخدام نفس الـ design system الحالي.
- الحفاظ على دعم الموبايل بالكامل.
- عدم كسر:
  الإشعارات
  المصادقة
  RBAC
  الدردشات
  الإعلانات الحالية
  التوثيق

--------------------------------------------------

6) قبل تنفيذ أي تعديل:
قم أولًا بتحليل:
- routes
- admin pages
- action handlers
- existing edit forms
- RBAC permissions
- database schema

ثم:
- أعد استخدام المكونات الحالية بدل إنشاء نظام جديد.
- أصلح المشاكل بأقل تغييرات ممكنة.
- تجنب أي refactor كبير.

--------------------------------------------------

7) بعد الانتهاء:
قم بعرض:
- الملفات التي تم تعديلها
- ما الذي تم إصلاحه
- أي migration تم إضافتها
- هل يحتاج deploy فقط أم migration أيضًا

ولا تقم بأي push أو deploy تلقائي.
