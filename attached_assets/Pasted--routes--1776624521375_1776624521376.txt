أريد تنفيذ تحسين معماري آمن جدًا وبشكل تدريجي للمشروع، مع الحفاظ الكامل على:

- نفس routes
- نفس UI والتصميم
- نفس سلوك الصفحة
- نفس API contract الحالي
- بدون كسر روابط
- بدون refactor كبير
- بدون تعديل backend أو database

🎯 المطلوب الآن: المرحلة 1 فقط
تحويل صفحة تفاصيل العقار `/properties/[id]` من Client-heavy إلى Server-first architecture بشكل آمن جدًا.

---

## الهدف

أريد أن تصبح صفحة `/properties/[id]` ترسم البيانات الأساسية من السيرفر بدل انتظار:
- useEffect
- useParams
- client fetch

لكن مع الإبقاء على الأجزاء التفاعلية فقط كـ client components.

---

## قواعد صارمة جدًا

1) لا تغيّر route إطلاقًا
- يجب أن تبقى الصفحة على نفس المسار:
  `/properties/[id]`

2) لا تغيّر التصميم
- نفس layout
- نفس spacing
- نفس ترتيب العناصر
- نفس الأزرار
- نفس السلايدر بصريًا
- لا تغيّر CSS إلا إذا كان ضروريًا جدًا

3) لا تغيّر backend أو response shape
- استخدم نفس API أو نفس مصدر البيانات الحالي
- لا تغيّر database
- لا تغيّر endpoints

4) لا تعمل refactor واسع
- أريد أقل عدد ملفات ممكن
- وأقل عدد تغييرات ممكن
- وتغييرات قابلة للتراجع بسهولة

---

## المطلوب معماريًا

### أ) اجعل الصفحة نفسها Server Component
إذا الصفحة حاليًا فيها:
- "use client"
- useParams
- useEffect لجلب بيانات العقار

أريد نقل جلب البيانات الأساسية إلى السيرفر.

يعني:
- الصفحة تستقبل params من Next.js
- تجلب بيانات العقار على السيرفر
- ترندر HTML الأساسي مباشرة

---

### ب) ما الذي يجب أن يكون Server-rendered؟
أريد هذه الأشياء تصل جاهزة من السيرفر:

- أول صورة أساسية للعقار
- عنوان العقار
- السعر
- الموقع
- أهم التفاصيل الأساسية
- metadata/SEO إن أمكن
- أي نص رئيسي ظاهر فوق fold

---

### ج) ما الذي يمكن أن يبقى Client-side؟
هذه الأشياء أبقها Client Components إذا كانت تحتاج تفاعل:

- ImageSlider التفاعلي بالسحب
- favorites toggle
- أي auth-dependent actions
- أي state محلي
- أي modals
- أي buttons تحتاج interaction فوري

لكن:
❌ لا تجعل الصفحة كلها client فقط بسبب هذه الأجزاء

---

### د) إن احتجت تقسيم الصفحة
افعلها بهذا الشكل فقط:

- Server wrapper/page
- Client subcomponents للتفاعل

مثال منطقي:
- page.tsx = server
- PropertyDetailsClient.tsx = client فقط إن لزم
- ImageSliderClient.tsx = client فقط إن لزم

لكن لا تغيّر الأسماء الحالية إلا إذا احتجت، ولا تنشئ تعقيدًا غير ضروري.

---

## الصور و LCP

- أول صورة أساسية في صفحة العقار يجب أن تكون محسنة
- إذا أمكن استخدم next/image
- أول صورة مهمة:
  - priority إذا كانت LCP فعلًا
  - sizes مناسبة
- لا تستخدم dynamic import أو ssr:false لأول صورة مهمة

---

## SEO

إذا كان ذلك آمنًا:
- اجعل metadata الأساسية تأتي من بيانات العقار
- title
- description
- og image إن كان سهلًا وآمنًا

لكن:
❌ لا تدخل في refactor كبير من أجل SEO الآن
✅ فقط تحسينات آمنة وسريعة

---

## المطلوب قبل تعديل الكود
أولًا:
1. اعرض لي باختصار:
   - ما الملف الحالي المسؤول عن `/properties/[id]`
   - ما الذي فيه الآن من use client / useEffect / useParams
   - ما الخطة الدقيقة بأقل تغيير ممكن

ثم بعد ذلك:
2. نفّذ التعديل بأقل diff ممكن

---

## المطلوب بعد التنفيذ
أعطني تقريرًا واضحًا جدًا يتضمن:

1. الملفات التي عدلتها فقط
2. ما الذي أصبح Server-side
3. ما الذي بقي Client-side
4. هل تغيّر أي route؟ (يجب أن تكون الإجابة: لا)
5. هل تغيّر أي تصميم؟ (يجب أن تكون الإجابة: لا)
6. هل ما زالت الصفحة تعمل بنفس السلوك؟ 
7. هل يوجد أي risk أو TODO صغير متبقٍ؟

---

## اختبارات إلزامية بعد التنفيذ

بعد التعديل، أريد منك أن تتحقق من:

- build passes
- لا يوجد TypeScript errors
- لا يوجد runtime errors
- صفحة `/properties/[id]` تفتح بشكل طبيعي
- الصورة الأولى تظهر
- السلايدر يعمل
- الأزرار التفاعلية تعمل
- لا يوجد كسر في التصميم
- لا يوجد كسر في الروابط الداخلية

---
